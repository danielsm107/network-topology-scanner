# Fase 4 (AWS como código + hallazgos) — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** cuando el escaneo nocturno encuentra cambios, llega un email corto (sensibles primero) con
enlaces temporales al mapa y al CSV en S3; el historial se copia a S3 tras cada escaneo y se restaura
siguiendo un runbook; el Terraform de AWS se aplica desde GitHub Actions por OIDC.

**Architecture:** La app gana dos flags genéricos (v1.4.0): `--changes-dir` (escribe `cambios.json`,
`asunto.txt` y `cuerpo.txt` solo si hay cambios; el texto lo genera `export.py`) y `--history-backup`
(copia consistente con la API de backup de SQLite, en `history.py`). Una raíz de Terraform nueva,
`infra/aws/hallazgos/`, crea bucket de informes, SNS, usuario IAM del homelab y OIDC + dos roles; la
aplica un workflow nuevo. En el chart, el Job nocturno pasa a escaneo (`initContainer`) + subida
(`amazon/aws-cli`, contenedor principal) compartiendo un `emptyDir`.

**Tech Stack:** Python 3.10+ (sqlite3, json), Terraform 1.16.6 + provider `hashicorp/aws`, GitHub
Actions (OIDC, environments), Helm 3, `amazon/aws-cli`.

**Spec:** `docs/superpowers/specs/2026-11-06-fase-4-aws-design.md` (y el diseño general
`2026-10-22-fase-devops-design.md`, fila 4).

## Global Constraints

- Rama `fase-4-aws`. Un commit por tarea; `.venv/Scripts/pytest tests/ -v` y
  `.venv/Scripts/ruff check src/ tests/ scripts/` en verde antes de cada commit.
- Coste: nada encendido (EC2, Lambda, NAT), **sin KMS propio** (SSE-S3 `AES256`), sin Glacier.
- La app no importa nada de AWS (`boto3`, nombres de bucket, ARNs) en `src/`.
- Grafo de imports intacto: `export → classifier, history`; `history → classifier`.
- Sin los flags nuevos, el CLI se comporta exactamente como en la v1.3.1. Sin `aws.enabled`, el chart
  renderiza lo mismo que en la fase 3.
- Textos de la interfaz y del email en inglés; docstrings, comentarios y docs en castellano.
- Asunto del email: **ASCII, sin saltos de línea, ≤ 100 caracteres** (límite de SNS). Marcador de
  sensibles `[!]`, nunca `⚠`.
- Datos inventados en tests, docs y valores versionados (`192.0.2.0/24`, `198.51.100.0/24`, MACs
  `02:00:00:…`, cuenta `123456789012`, email `alerts@example.com`). El email real, el ID de cuenta y
  las claves no van a git.
- Región `eu-south-2`. Estado en el bucket del bootstrap, clave `hallazgos/terraform.tfstate`,
  `use_lockfile = true`.
- Retenciones: `informes/` 90 días; versiones no actuales de `historial/` 30 días. Enlaces prefirmados
  de **604800 s** (7 días).
- Repo `danielsm107/network-topology-scanner`; environment de GitHub `aws`.
- Actions de terceros por SHA con `# vX.Y.Z`; runners `ubuntu-26.04`; imagen `amazon/aws-cli` por
  digest (`@sha256:…`). Lo comprueban `tests/test_workflows.py` y `tests/test_helm.py`.
- Lo marcado **[A MANO]** lo hace el mantenedor, con Claude supervisando. Nunca se muestran claves.

## Review Focus

1. **Primer escaneo de un rango nuevo** (`primera_vez`) junto a otro rango sin cambios → no se escribe
   nada ni hay email → `test_changes_dir_primera_vez_no_escribe_nada` (Tarea 3).
2. **Muchos rangos o muchos cambios** → el asunto se recorta sin pasar de 100 caracteres y sigue siendo
   ASCII aunque el hostname/vendor tenga acentos (solo el cuerpo los lleva) →
   `test_asunto_ascii_y_max_100_con_muchos_rangos` (Tarea 2).
3. **Host nuevo sin MAC ni hostname** (otro segmento L2) → línea con IP y `unknown vendor`, sin
   `KeyError` → `test_cuerpo_host_sin_vendor` (Tarea 2).
4. **Copia del historial mientras otro proceso escribe** → la copia es una base válida y completa, no un
   archivo a medias → `test_copiar_historial_con_escritura_abierta` (Tarea 1).
5. **Falla el historial (`HistoryError`)** → el escaneo sigue (como hoy), no se escribe `cambios.json`
   ni copia, y el CLI no revienta → `test_changes_dir_y_backup_si_falla_el_historial` (Tarea 3).

### Task 2: Texto del email (`export.resumen_cambios_email`)

**Files:**
- Modify: `src/topology_scanner/export.py`
- Test: `tests/test_export.py`

**Interfaces:**
- Consumes: `history.hay_cambios`, `history.combinar_diffs`; diffs con el formato de `_comparar`;
  resultados con el formato de `scanner.parsear_host`.
- Produces: `resumen_cambios_email(diffs: dict[str, dict], resultados: dict) -> tuple[str, str] | None`
  — `(asunto, cuerpo)`, o `None` si ningún diff tiene cambios (`hay_cambios` y no `primera_vez`).
  Constante `MAX_ASUNTO = 100`.

Formato (texto exacto de cabeceras; el resto de espaciado a criterio):

```
Asunto: [topology-scanner] [!] 1 sensitive port - 3 changes in 192.0.2.0/24, 198.51.100.0/24
        ([!] ... - solo si hay sensibles; solo los rangos con cambios; nº de cambios =
        hosts nuevos + hosts caídos + hosts con puertos cambiados)

Cuerpo:
SENSITIVE PORTS
  [!] 192.0.2.20 - 3389 RDP (common brute-force target)

NEW HOSTS
  192.0.2.57  host.example  Espressif  (iot)

DOWN HOSTS
  192.0.2.30

PORT CHANGES
  192.0.2.20  new: 3389  closed: 80
```

Secciones vacías se omiten. Hosts caídos solo con IP (no están en `resultados`). Host sin vendor →
`unknown vendor`; sin hostname, se omite ese campo.

- [ ] **Step 1: Tests**
  - `test_resumen_none_sin_cambios` (diff sin cambios) y `test_resumen_none_primera_vez`.
  - `test_resumen_sensibles_primero`: con un sensible y un host nuevo, `cuerpo.index("SENSITIVE PORTS")
    < cuerpo.index("NEW HOSTS")` y `asunto.startswith("[topology-scanner] [!] 1 sensitive port")`.
  - `test_resumen_solo_rangos_con_cambios_en_asunto`: dos rangos, uno sin cambios → solo aparece el otro.
  - `test_asunto_ascii_y_max_100_con_muchos_rangos`: 10 rangos con cambios → `len(asunto) <= 100`,
    `asunto.isascii()`, sin `\n`.
  - `test_cuerpo_host_sin_vendor`: host nuevo con `vendor=""`, `hostname=""` → la línea contiene la IP y

Decisiones fijadas:

- Rol plan: trust `token.actions.githubusercontent.com:sub = repo:<repo>:pull_request`, `aud =

- Rol apply: trust `sub = repo:<repo>:environment:<environment_apply>`. Escritura limitada a ARNs

  sobre la clave y su `.tflock`).
- Bucket: nombre `topology-scanner-informes-${account_id}`, bloqueo público total, `AES256`,
  versionado `Enabled`, lifecycle: `informes/` expira a 90 días (+ versiones no actuales a 1 día),
